## How the connectors keep spending bounded

1. Payer, tenant, cluster, spend policy and signer are set by the host when the connector is built; no tool input can change them.
2. `rufus.create_task` accepts only the digest of a preview the same session produced.
3. Every financial tool calls the host's `authorize()` callback. It must return a `SpendAuthorization` signed by a principal registered for the tenant and wallet, bound to the action, cluster, program, budget, preview digest or task, with a single-use nonce and expiry. Returning `null` leaves nothing signed.

## x402

Select integrations are custom escrow integrations, not x402 schemes. `create_task_v2` is not renamed `exact`, `upto` or `batch`, and no x402 charge is added on top of an escrowed obligation.

## Discovery

`/.well-known/rufus-capabilities.json` (namespace `rufus`, schema `rufus.capabilities.v1`), `/llms.txt` and `/openapi.json` describe the service (the `rufus` names are technical identifiers kept for compatibility). Publishing them does not register Select with any framework, registry or agent directory. The Lucid manifest (`buildAgentManifest`) is generated by Lucid's own code; no Solana-specific agent-card standard is invented here.
